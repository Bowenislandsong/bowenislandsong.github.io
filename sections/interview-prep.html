Coding Interview Prep

Train the instinct, not just the final code.

This page is a Google-style interview drill board organized two ways: by problem category and by solution approach. The goal is not to memorize answers. The goal is to recognize the smell of the problem, choose the right framing quickly, and explain the tradeoffs clearly.

Every problem links to the official LeetCode page and includes the instinct, the core move, the edge cases to call out, and the Big O analysis you should be able to say out loud in an interview.

The drill set now covers the major interview families: arrays and windows, binary search, intervals, greedy reasoning, monotonic stacks, trees, heaps, graphs, dynamic programming, linked lists, strings, backtracking, bit tricks, and tries.

It also now includes a smaller niche layer: line sweep, Fenwick or segment trees, geometry and selection patterns like quickselect, and design-heavy cache or system-style prompts. It still does not claim to be literally exhaustive. The next layer after this would be things like lazy propagation, MST and SCC variants, harder geometry, bitmask DP, and concurrency-heavy design prompts.

How To Use This Page

1. Start with the smell

Ask what structure is hidden: sliding window, interval list, sorted array, tree, heap frontier, graph, linked list cycle, prefix tree, bounded search, or sequence alignment.

2. Say the invariant

A strong interview answer names the invariant clearly before writing code: what a DP cell means, what a window means, what BST bounds mean, what a pointer means, or what a shortest-path distance means.

3. Mention the traps

Leading zeros, duplicate skipping in 3Sum, off-by-one binary-search boundaries, stale heap entries, disconnected graphs, and odd-length linked lists are the kinds of edge cases interviewers want to hear proactively.

This is framed as a high-signal public prep set for Google-style interviews. It is intentionally broader now, but it is still representative rather than exhaustive, and company question frequency shifts over time.

Python Interview Toolbox

Short things worth remembering cold.

These are not full patterns by themselves. They are the small language tools that make common interview solutions cleaner, faster to write, and easier to explain.

collections.deque

Queue

Double-ended queue with O(1) append and pop from both ends.

Remember

from collections import deque
q = deque([start])
q.append(x)
node = q.popleft()

Useful for: BFS, level-order traversal, fixed-size windows, monotonic queues.

Typical prompts: Number of Islands with BFS, Rotting Oranges, Binary Tree Level Order Traversal.

When not to use: not for random indexed access in the middle; a list or array is better there.

collections.defaultdict

Map

Dictionary with an automatic default value factory, so you do not need repetitive existence checks.

Remember

from collections import defaultdict
graph = defaultdict(list)
count = defaultdict(int)

Useful for: adjacency lists, frequency maps, grouping values.

Typical prompts: graphs, topological sort, prefix-sum counting, anagram grouping.

When not to use: avoid it when accidental key creation would hide bugs, especially in stateful design questions.

collections.Counter

Count

Frequency table for hashable items. Great when the main state is just counts.

Remember

from collections import Counter
freq = Counter(nums)
same = Counter(s) == Counter(t)

Useful for: frequency matching, top-k setup, multiset comparison.

Typical prompts: valid anagram, top-k frequent elements, sliding-window count matching.

When not to use: not ideal when the alphabet is tiny and fixed, because a small array can be simpler and faster.

heapq

Heap

Min-heap in Python. The smallest item comes out first, so push negative values when you want max-heap behavior.

Remember

import heapq
heapq.heappush(heap, (priority, node))
priority, node = heapq.heappop(heap)

Useful for: Dijkstra, merge-k structures, streaming top-k, always-take-smallest problems.

Typical prompts: Network Delay Time, Top K Frequent Elements, meeting rooms, kth largest.

When not to use: if you need fast deletion or update of arbitrary existing entries, a plain heap gets awkward and usually needs stale-entry handling.

bisect_left

Binary Search

Returns the first index where x could be inserted while keeping the array sorted, which means the first index with value >= x.

Remember

from bisect import bisect_left
i = bisect_left(nums, target)

Useful for: lower-bound search, insertion position, patience-sorting style LIS solutions.

Typical prompts: search insert position, LIS optimization, first valid position in sorted data. Its sibling bisect_right is the one to remember for “latest timestamp <= t” lookups like TimeMap.

When not to use: it only helps if the data is already sorted or maintained in sorted order; otherwise the setup cost can erase the benefit.

OrderedDict

LRU

Modern dict already preserves insertion order, but OrderedDict is still useful when you need explicit recency operations.

Remember

from collections import OrderedDict
cache.move_to_end(key)
oldest_key, _ = cache.popitem(last=False)

Useful for: LRU cache style questions where keys must be moved to “most recent” and evicted from the “least recent” side.

Typical prompts: LRU Cache, explicit recency tracking, ordered eviction logic.

When not to use: do not reach for it just because you want insertion order; plain dict already gives that in modern Python.

functools.lru_cache

Memo

Memoizes a pure recursive function by caching arguments, which can collapse exponential recursion into polynomial time.

Remember

from functools import lru_cache
@lru_cache(None)
def dfs(i, j): ...

Useful for: DFS on DAG-like state spaces, DP with recursion, repeated subproblems.

Typical prompts: Longest Increasing Path in a Matrix, word break variants, recursive DP on indices.

When not to use: avoid it if the function depends on mutable external state or if the cached state space is too large to fit comfortably in memory.

Problem Categories

Choose the family before you choose the code.

Category filters answer: what kind of object am I really working with? A sequence or interval list, a graph, a tree, a mutable range-query structure, a linked list, a coordinate geometry object, a combinatorial search tree, a prefix structure, or an API with operation constraints.

Solution Approaches

Train pattern recognition by technique.

Approach filters answer: what move unlocks the problem? Sweep events, slide a window, binary search the answer, partition around the kth boundary, relax edges, use a heap frontier, update a Fenwick tree, peel indegrees, reverse the list, or prune by prefix.

Study Playbook

What to practice out loud.

Name the state

Before coding, say what each state means. Examples: “dp[i][j] is the cost to convert prefixes,” “dist[node] is the best known arrival time,” or “slow and fast are walking a hidden cycle.”

Name the monotone property

Before using binary search, a monotonic stack, or greedy reachability, say what stays ordered. Examples: “if speed s works, any larger speed works,” “the stack stays decreasing by temperature,” or “furthest reach summarizes every jump choice so far.”

Name the pruning rule

Strong interviewers look for disciplined search. Say what kills a branch early: invalid prefix, duplicate subset generation, impossible remaining target, or already-computed memo state.

Name the failure mode

Mention the wrong instinct too. “Forward simulation mutates neighbors.” “Greedy local choice fails.” “I cannot move backward in a singly linked list.” That makes the final solution feel justified, not magical.
